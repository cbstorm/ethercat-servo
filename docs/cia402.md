# CiA 402 implementation

## State decoding (0x6041)

| State | Mask | Value |
|---|---|---|
| Not Ready to Switch On | 0x004F | 0x0000 |
| Switch On Disabled | 0x004F | 0x0040 |
| Ready to Switch On | 0x006F | 0x0021 |
| Switched On | 0x006F | 0x0023 |
| Operation Enabled | 0x006F | 0x0027 |
| Quick Stop Active | 0x006F | 0x0007 |
| Fault Reaction Active | 0x004F | 0x000F |
| Fault | 0x004F | 0x0008 |

## Controlword selection

`Cia402Drive` keeps a *request*: Enable, Disable, QuickStop or DisableVoltage. Every cycle it selects the controlword from the **decoded state** and that request. It never sends a fixed sequence blindly.

| Current state | Enable | Disable | QuickStop | DisableVoltage |
|---|---|---|---|---|
| Switch On Disabled | 0x0006 Shutdown (2) | 0x0000 | 0x0000 | 0x0000 |
| Ready to Switch On | 0x0007 Switch On (3) | 0x0000 (7) | 0x0000 | 0x0000 |
| Switched On | 0x000F Enable Op (4) | 0x0000 (10) | 0x0000 | 0x0000 |
| Operation Enabled | 0x000F | 0x0007 Disable Op (5) | 0x0002 Quick Stop (11) | 0x0000 (9) |
| Quick Stop Active | 0x0000 (12), then via Switch On Disabled | 0x0000 (12) | 0x0002 (hold) | 0x0000 |
| Fault / Fault Reaction / Not Ready | 0x0000 | 0x0000 | 0x0000 | 0x0000 |

- **Fault reset:** bit 7 is held low for at least 2 cycles, then high for `fault_reset_pulse` (rising edge), then low again. The result is checked with a timeout. A reset is ignored on a healthy drive. After a reset the request is *Disable*: **a drive is never re-enabled automatically after a fault.**
- **Transition timeout** (`timeouts.state_transition_ms`): if the decoded state does not change while the request is unsatisfied, a `transition_timeout` is reported (safety fault), and an Enable request falls back to Disable. Waiting in Fault is not counted.
- **Re-enable after quick stop** always goes through Switch On Disabled, not transition 16, so the behavior does not depend on the quick-stop option code.
- **Enable never jumps:** while the drive is not Operation Enabled, the CSP target position tracks the actual position. The trajectory starts from the actual position.
- **Controlled disable:** if the axis is moving, `disable()` first ramps to standstill (CSP/CSV/CST loops: own trajectory; PP: halt bit; PV: target velocity 0), then requests Disable.
- The controlword is recomputed after commands and safety reactions in the same cycle, and also when no fresh feedback arrived (incomplete WC). A safety reaction therefore always reaches the PDO.

## Modes

| Mode | Value | Who generates the profile | Required PDO objects | Parameters (PDO if mapped, otherwise async SDO) |
|---|---|---|---|---|
| CSP | 8 | Library (trapezoid, sampled each cycle) | 0x607A | – |
| CSV | 9 | Library (velocity ramp; optional PID position loop) | 0x60FF | – |
| CST | 10 | Library (torque command or PID loop) | 0x6071 | – |
| PP | 1 | Drive | 0x607A | 0x6081, 0x6083, 0x6084 |
| PV | 3 | Drive | 0x60FF | 0x6083, 0x6084 |
| Homing | 6 | Drive | – | 0x6098, 0x6099:1/2, 0x609A |

Always required: 0x6040, 0x6041, 0x6064. Recommended: 0x6061 (mode confirmation), 0x606C (velocity), 0x603F (error code), 0x6077 (torque).

### Mode switching

`setMode()` is accepted only while the axis is idle. It writes 0x6060 by PDO if mapped, otherwise by a non-blocking SDO request created before activation. The switch completes when 0x6061 shows the new mode, or when the write succeeded if 0x6061 is not mapped. It fails after `timeouts.mode_switch_ms`. During the switch the position setpoint tracks the actual position.

### PP handshake

1. Write profile velocity, acceleration and deceleration (PDO or SDO).
2. Set target 0x607A, then controlword bit 4 (new set-point) + bit 5 (change immediately).
3. Wait for statusword bit 12 (set-point acknowledge), then clear bit 4.
4. Done when bit 12 = 0 and bit 10 (target reached) = 1.

Stop uses bit 8 (halt), which stays set until the next set-point. Relative moves are converted to absolute targets by the library.

### Homing

`home()` saves the current mode, writes the method, speeds and acceleration, switches to mode 6, then sets bit 4.

- Success: bit 12 (homing attained) and bit 10 (target reached).
- Failure: bit 13 (homing error), or `homing.timeout_s` expires.

The previous mode is restored, and the setpoint is resynchronized to the new actual position. `setPosition(p)` is a software alternative that redefines the current position without moving.

## Units

```
counts = units / units_per_revolution * gear_ratio * counts_per_revolution * direction
drive velocity = units/s * counts_per_unit * velocity_factor
drive accel    = units/s^2 * counts_per_unit * acceleration_factor
torque [0.1 %] = percent * 10 * direction
```

`setPosition()` adds a software offset in counts. Successful drive homing resets that offset to 0, because the drive redefines its own position.

## Statusword bits used

| Bit | Use |
|---|---|
| 7 | Warning (reported) |
| 10 | Target reached (PP, PV, Homing) |
| 12 | PP set-point acknowledge / Homing attained |
| 13 | Homing error |

Following error is supervised by the library (|setpoint − actual| > `following_error_max` for N cycles) in CSP and with external position loops. The drive's own following-error handling (0x6065/0x6066) remains active.
